Early access

Early access opens November 2026.

Early access is the self-hosted Driftnet daemon, run on your own network with a baseline fitted to your own traffic. Join the list and you get an email when it opens.

  • It runs on your machine. The daemon makes no outbound connections unless you configure an alert webhook.
  • It sits behind what you have. Point it at a Suricata eve.json or a Zeek conn.log, or let it capture on its own.
  • It is pre-release. Measured on recorded captures so far, not yet on a live interface. See exactly where it stands

What you will do

Record, run, read.

Three steps from a recording of your network to explained alerts. A day of baseline is the minimum worth having; a week is better.

01 · record

Fit a baseline from your own traffic

Record normal traffic from an interface, or read an existing capture or log. Whatever is in the recording becomes normal, so record when you believe the network is clean. 

$ sudo python -m snortml_inference \
    baseline --source eth0 \
    --duration 86400
02 · run

Score live traffic, or a growing log

Capture on an interface, or follow the log your Suricata or Zeek sensor already writes. Following a log needs read access only, no capture privileges. 

$ sudo python -m snortml_inference \
    run --interface eth0
03 · read

Triage alerts that explain themselves

Each alert says how rare the event is and which measurements made it so. One JSON object per alert, ready for Wazuh or any SIEM, or a webhook. 

$ tail -f alerts/alerts.jsonl

No network to spare? replay runs a recorded pcap, conn.log or eve.json through exactly the code the daemon runs and prints what would have alerted.

Before you sign up

What you need, and what to expect.

What you need

Nothing exotic.

  • A 64-bit Linux machine that can see the traffic you care about, with Python 3.10 or newer and libpcap
  • Or logs you already have: a Suricata eve.json or a Zeek conn.log
  • A day or more of traffic you believe is clean, to fit the baseline
  • No GPU, no TensorFlow, no ONNX runtime. Scoring is plain numpy
What to expect

It is early. Plainly:

  • You may be first. Live interface capture, Windows and Raspberry Pi are built but not yet verified
  • A budget of 10 alerts a day by default, which is yours to change
  • Blind spots. It does not catch beacons or tunnels today
  • Alerts are leads, not verdicts. Rare is not the same as malicious
  • A command line. There is no dashboard; alerts are files and webhooks
Questions

Asked before signing up.

Does anything leave my network?

No. The daemon reads traffic or logs and writes alerts to local files. The one exception is the alert webhook, which posts each alert to a URL you choose, and is off unless you set it.

The baseline, recorded flows, alerts and logs all contain your network's addresses. They stay on the machine that runs the daemon.

Does it replace Suricata, Snort or Zeek?

No. The signature IDS stays the first layer and owns everything its rules catch. Driftnet is the second layer: it reports what is unusual in the traffic the rules let through. It also runs on its own if you have no IDS.

How long before it is useful?

It needs a baseline first. A day of normal traffic is the minimum worth having and a week is better. After that the daemon keeps the flows it sees, and one command re-fits the baseline as your network changes.

Will it run on Windows or a Raspberry Pi?

It is built to: Windows through Npcap, and 64-bit Raspberry Pi OS. Neither has been verified on this version yet, so 64-bit Linux is the safe choice for early access. 32-bit ARM is not supported.

Is it open source?

Not today. No licence has been published yet. The status page will say so when one is.

What happens to my email address?

It goes on the early-access list, with the role you picked if you picked one. It is used to tell you when access opens and, occasionally, what early testers are finding. Nothing else.
